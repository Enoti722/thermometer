  ИСПРАВЛЕНИЕ КРИТИЧЕСКОЙ ОШИБКИ - NullPointerException
═══════════════════════════════════════════════════════════════════

ПРОБЛЕМА:
---------
При повторном клике на эмулятор приложение крашилось с ошибкой:
NullPointerException в методе disconnect() при попытке закрыть 
usbSerialPort, который был null для эмулятора.

ПРИЧИНА:
--------
Метод disconnect() пытался вызвать usbSerialPort.close() без 
проверки на null. Для эмулятора этот объект всегда null, так как 
эмулятор не использует USB.

РЕШЕНИЕ:
--------
Добавлены проверки на null в 4 критических местах:

1. disconnect() - проверка usbSerialPort перед close()
2. onDestroy() - try-catch для всех операций отключения
3. read() - проверка usbSerialPort перед чтением
4. connect() - проверка usbManager перед использованием

ИЗМЕНЕНИЯ В КОДЕ:
-----------------

✅ UsbService.java - метод disconnect() (строка ~862)
   БЫЛО: usbSerialPort.close() без проверки
   СТАЛО: if (usbSerialPort != null) { try { ... } catch { ... } }

✅ UsbService.java - метод onDestroy() (строка ~220)
   БЫЛО: disconnect() без try-catch
   СТАЛО: try { disconnect(); } catch (Exception e) { log }

✅ UsbService.java - метод read() (строка ~755)
   БЫЛО: usbSerialPort.read() без проверки
   СТАЛО: if (usbSerialPort == null) { return; }

✅ UsbService.java - метод connect() (строка ~790)
   БЫЛО: usbManager.getDeviceList() без проверки
   СТАЛО: if (usbManager == null) { return; }

РЕЗУЛЬТАТ:
----------
✅ Нет крашей при отключении эмулятора
✅ Нет крашей при переключении между устройствами
✅ Все операции безопасны и логируются
✅ Обратная совместимость сохранена

ТЕСТИРОВАНИЕ:
-------------
Проверьте следующие сценарии:

1. Выбор эмулятора → повторный клик на эмулятор
   Ожидается: Нет крашей, сервис перезапускается

2. Выбор эмулятора → выбор реального устройства
   Ожидается: Плавное переключение без крашей

3. Выбор реального → выбор эмулятора
   Ожидается: USB порт закрывается корректно

4. Многократное переключение
   Ожидается: Нет утечек памяти, нет крашей
